# Architecture Review
Generated: 2026-07-28T18:37:05.186Z
Score: 64/100

## Summary
The codebase is a fairly small, well-commented App-in-Toss mini-app (sleep debt tracker) with good component reuse for TDS-wrapped UI primitives (Card, ScreenScaffold, Amount, etc.). However, it suffers from repeated boilerplate across page components (date formatting, haptic wrappers, tab bar config), several leftover/dead files from debugging and an abandoned page variant, and inconsistent conventions for imports and storage access. No circular dependencies were found.

## Issues
### Critical
- [naming] Two competing home-page implementations exist (`Home.tsx` and `HomePage.tsx`) in the same folder with inconsistent naming; only `HomePage.tsx` is wired into `App.tsx`, making `Home.tsx` an orphaned, confusing duplicate. — Files: src/pages/Home.tsx, src/pages/HomePage.tsx, src/App.tsx / Fix: Delete `Home.tsx` (or rename/merge it into `HomePage.tsx`) so there is a single canonical home page, and standardize all page files on the `*Page.tsx` suffix.
- [dead_code] `src/pages/Home.tsx` is never imported by `App.tsx` or any router — it's fully unreachable dead code duplicating `HomePage.tsx`'s responsibility. — Files: src/pages/Home.tsx, src/App.tsx / Fix: Remove the file, or if it was meant as a template/reference, move it out of `src/pages` (e.g. into docs/examples) so it isn't mistaken for live code.

### Warnings
- [duplication] `todayISO()` is copy-pasted verbatim (same implementation, same name) in four different page files instead of living in a shared date utility module. — Files: src/pages/HomePage.tsx, src/pages/InputPage.tsx, src/pages/PlanPage.tsx, src/pages/ReportPage.tsx / Fix: Extract to `src/lib/date.ts` as `export function todayISO(): string { ... }` and import it everywhere instead of redefining locally.
- [duplication] A `fireHaptic()` try/catch wrapper around `generateHapticFeedback` is reimplemented independently in at least five files with only minor type-union differences, instead of a single shared helper. — Files: src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx, src/components/OnboardingNotice.tsx, src/pages/HomePage.tsx, src/pages/InputPage.tsx, src/pages/PlanPage.tsx, src/pages/ReportPage.tsx / Fix: Create `src/lib/haptics.ts` exporting `fireHaptic(type: HapticType)` that wraps the try/catch once, and have every caller import it.
- [duplication] The exact same 4-item `FloatingTabBar` `items` array (홈/리포트/플랜/진단 with hardcoded paths) is inlined in every page that renders the tab bar, so adding/removing/reordering a tab requires editing 4 files in sync. — Files: src/pages/HomePage.tsx, src/pages/PlanPage.tsx, src/pages/ReportPage.tsx, src/pages/DiagnosisPage.tsx / Fix: Define a single `MAIN_TABS: TabItem[]` constant (e.g. in `src/lib/navigation.ts` or next to `FloatingTabBar`) and import it in each page.

- [consistency] Import path style is inconsistent: newer pages/components use the `@/` alias (`@/components/...`, `@/lib/...`) while `App.tsx`, `Home.tsx`, `Amount.tsx`, and `CountUp.tsx` use relative paths (`../lib/utils`, `./pages/HomePage`) for the same kind of internal module. — Files: src/App.tsx, src/pages/Home.tsx, src/components/Amount.tsx, src/components/CountUp.tsx, src/pages/HomePage.tsx / Fix: Pick one convention (the `@/` alias is already configured and used by the majority of newer files) and migrate remaining relative imports to match; enforce via an eslint import-path rule.
- [consistency] Storage access pattern is inconsistent: most pages call domain-typed helpers from `lib/storage.ts` (`getRecords`, `getSettings`, `saveRecord`, `getRewardUnlock`...), but `DiagnosisPage.tsx` bypasses this layer and calls the generic `getItem`/`setItem`/`removeItem` directly with raw `SDT_KEYS`, losing the `safeSet`/`safeGet` error handling (`STORAGE_FULL`) and typed shape guarantees the rest of the app relies on. — Files: src/pages/DiagnosisPage.tsx, src/lib/storage.ts / Fix: Add a typed `getChronotype`/`setChronotype`/`clearChronotype` API (matching the pattern of `getRewardUnlock`/`setRewardUnlock`) in `lib/storage.ts` and have `DiagnosisPage` use it instead of the generic key-value helpers.

### Suggestions
- [duplication] `formatDebtHM` (HomePage.tsx) and `formatHoursMinutes` (ReportPage.tsx) implement identical minutes→"Xh Ym" formatting logic under different names, and PlanPage likely needs the same formatting. — Files: src/pages/HomePage.tsx, src/pages/ReportPage.tsx / Fix: Consolidate into one exported function (e.g. `formatMinutesAsHM` in `src/lib/sleepEngine.ts` or `src/lib/utils.ts`) with one canonical name.
- [duplication] `Amount.tsx` and `CountUp.tsx` duplicate the same nowrap/tabular-nums wrapper `<span>` markup and style object almost verbatim; only the value-computation logic differs. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract the shared `<span style={{...}}>` wrapper into a small internal `NumericText` helper that both components render into.
- [dead_code] `src/__probe.tsx` and `src/__rrcheck.ts` look like ad-hoc react-router debugging scaffolding (console.log probes, raw re-exports of `useLocation`/`MemoryRouter`) with no imports from any production file. — Files: src/__probe.tsx, src/__rrcheck.ts / Fix: Delete these debug files from `src/`, or move them into a `scripts/` or `debug/` folder excluded from the build if still needed.
- [dead_code] `formatCurrency` and `cn` in `lib/utils.ts` are not referenced by any shown file (the app only ever formats sleep minutes/counts via `formatNumber`), suggesting leftover boilerplate from a template. — Files: src/lib/utils.ts / Fix: Remove unused exports, or confirm usage elsewhere in the codebase; keep `lib/utils.ts` scoped to what's actually consumed.
- [structure] `pages/__TdsGallery.tsx` (dev-only component gallery) sits inside `src/pages` alongside real routed pages, relying only on a naming convention (`__` prefix) and a comment to signal it's excluded from prod. — Files: src/pages/__TdsGallery.tsx, src/App.tsx / Fix: Move dev-only reference pages to a dedicated `src/dev/` directory so tree-shaking/exclusion doesn't depend solely on filename convention and code review vigilance.
- [consistency] Full-screen reward-ad gating logic (load ad, timeout, unlock, error toast) is duplicated with slight variations directly inside `PlanPage` and `ReportPage`, rather than both using the existing (currently unused) `TossRewardAd` component. — Files: src/pages/PlanPage.tsx, src/pages/ReportPage.tsx, src/components/TossRewardAd.tsx / Fix: Refactor both pages to wrap gated content in `<TossRewardAd slotId=... onRewarded=...>`, removing the duplicated ad-state machine from each page.
